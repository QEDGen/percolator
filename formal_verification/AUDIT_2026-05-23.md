## Root cause analysis

Six of the 15 closures fell to partial. They cluster into two
recognizable shapes:

1. **"Structural locality" via function signature** (#12, #65, #85) —
   the Lean model defines a function whose input type is "small"
   (single record, indexed lookup), and observes that the
   *signature* rules out scanning unwanted state. This is a real
   fact about the Lean spec, but the spec rule asks about the
   *production engine*: does v16.rs's actual code respect the
   same locality? The Lean model is a different function from the
   production one. The closure captures intent, not behavior.

2. **"Type-level isolation" via phantom types or tag sums** (#3,
   #54, #63) — the Lean model uses phantom-typed records or
   closed-sum tags to make cross-domain combinations a type
   error. The production engine implements the same intent via
   runtime field comparisons. Lean's type system witness doesn't
   transfer to the production model.

Both shapes produce *real Lean theorems* that match the spec's
description, but neither constrains the production engine's
behavior directly. They are spec-correctness witnesses, not
refinement witnesses.

## Recommended actions

The 6 partials are strengthenable using the same patterns the
audit doc developed in May:

- **#3** — Model a `DualProofEmit` function whose codomain is the
  product `ReservationEncumbranceProof × TokenValueFlow`, with
  the two halves independently validated. The "separately
  validated" half becomes structural.
- **#12, #65, #85** — Model a small fixed-cardinality state with
  explicit per-bucket / per-domain / per-asset bookkeeping. Prove
  that updates affect only the indexed slot. This lifts the
  structural locality from spec to a state-machine refinement.
- **#54** — Add a flat `AssetExposureWithIndex` (`assetIndex :
  Nat` as a runtime field) and a `combine : ... → Option Capital`
  function that returns `none` on index mismatch. The fail-closed
  on runtime index comparison mirrors production.
- **#63** — Add a `verifySignature : Signature → AccountId →
  Bool` predicate; require `CertOrigin.engineVerified` to carry
  a signature-validity proof field.

## Update — strengthenings applied

After the audit, all 6 partials were strengthened in a single
commit. Each module gained a production-aligned section:

- **#3 (ReservationEncumbrance)** — added `DualProofEmit`: a
  record carrying both the encumbrance proof *and* the value
  flow, with two *independent* validity proof fields. The
  structural witness for "engine emits and validates both
  separately" is that the two proof fields cannot reference each
  other; `encumbrance_validity_is_local` and
  `valueFlow_validity_is_local` witness the independence.

- **#12 (BoundedExpiryScan)** — added `BucketArray` with an
  indexed-function `slot : Nat → BackingBucket` and `updateAt :
  Nat → BackingBucket → BucketArray`. `updateAt_preserves_other_slots`
  proves a single-index update touches exactly one slot.
  `updateAt_expire_preserves_other_liveAvailable` lifts the
  locality to the `liveAvailable` projection.

- **#54 (CrossAssetIsolation)** — added `AssetExposureWithIndex`
  with a *runtime* `assetIndex : Nat` field (matching production).
  `combineWithCheck` returns `none` on index mismatch;
  `combineWithCheck_fails_on_mismatch` is the fail-closed
  witness; `combineWithCheck_preserves_index` proves a
  successful combine produces an exposure with the shared
  index — no path produces a "mixed" index.

- **#63 (VerifiedMaker)** — added `SignedPostTradeHealthCert`
  with a `Signature` record, a `verifySignature` predicate, and
  a structural proof field `signatureValid` requiring that
  `.engineVerified` carries a valid signature.
  `engine_verified_has_valid_signature` and
  `engine_verified_signature_under_engine_key` are the
  cryptographic-link witnesses.

- **#65 (AggregateDriftCredit)** — added `MaintainedAggregate`
  with `applyPositive` (per-delta increment) and `applySequence`
  (sequence of deltas). `applySequence_equals_sum` proves the
  cached aggregate equals the sum of all applied deltas — the
  incremental-maintenance invariant.

- **#85 (NoFullMarketScan)** — added `SingleInstruction` (carries
  one `target : AssetIndex`) and `executeBatch` (sequence of
  single instructions). `execute_preserves_all_other_slots`
  proves a single instruction touches exactly its target;
  `executeBatch_preserves_slot_when_not_in_targets` proves the
  batch's touched slots ⊆ the batch's target list.

After these strengthenings: **9 → 15 SOLID, 6 → 0 PARTIAL,
0 OVERCLAIM**. Effective coverage on the 15-row audit subset
moves from 80% to 100%.
